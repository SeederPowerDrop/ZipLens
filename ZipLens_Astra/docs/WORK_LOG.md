# 함께 작업한 기록

## 사용자 요청 — 2026-09-05

첫 vibe coding으로 만든 macOS 압축 앱을 검토하고, 반디집 기능·개선 이력·벤치마크를 참고해 버그·편의·성능을 개선하기. 원본은 보존하고 `ZipLens_Astra`라는 새 폴더를 만들며 코드 주석과 개발자 노트를 남기기.

## 1. 보존과 조사

- 원본의 staged/unstaged 변경을 확인하고 그대로 복사했다. Git 기록을 정리하거나 덮어쓰지 않았다.
- node_modules·target·dist·release_build·.git은 복사 대상에서 제외하고 별도 의존성과 결과물을 만들었다.
- 158개 입력 파일의 SHA-256을 저장했다. 작업 후 대조에서도 원본 변경이 없었다.
- 사용자가 제공한 반디집의 세 페이지와 RustSec, 7-Zip 공식 배포 자료를 읽었다.

## 2. 핵심 판단

기능 수를 늘리기 전에 기존 폴더 삭제, 링크/경로 탈출, 실패를 성공으로 보고하는 문제부터 고쳐야 한다고 판단했다. ZIP 파일 수가 많을 때의 병목은 파일마다 반복되는 중앙 목록 파싱이었다.

## 3. 구현

- UI와 분리된 Rust core를 추가했다. 추출을 임시 공간에서 검증하고 목적지에 병합한다.
- 독립 파일 오프셋과 공유 중앙 목록, 취소, 진행 알림 제한, 암호/분할/메모리 한도를 구현했다.
- 공식 7-Zip 26.03으로 교체하고 obsolete sevenz-rust 의존성을 제거했다.
- 프런트엔드의 HTML 삽입, CSV 수식, 숨겨진 검색, 과도한 DOM 생성, 중복 라벨과 시작 이벤트 문제를 수정했다.
- 별도 앱 이름·식별자를 사용해 원본 설치 앱을 교체하지 않도록 했다.

## 4. 회귀 테스트에서 발견해 추가 수정한 문제

- Keep Both의 실제 파일 경로에 빈 경로를 join해 마지막 `/`가 붙던 오류.
- ZIP용 `-mcp=949`가 7z 열기에 적용되어 E_INVALIDARG를 발생시키던 오류.
- 디렉터리 선택을 7-Zip에 넘기면 해제하지 않으려던 자식까지 포함될 수 있는 문제.
- 디렉터리 권한을 임시 공간에 너무 일찍 적용하면 최종 반영/정리를 방해하는 문제.
- UI의 첫 클릭이 행을 다시 만들어 더블클릭을 방해하던 문제.
- TAR 작업 취소를 Interrupted로 반환하면 내부 복사 루프가 재시도할 수 있는 문제. 터미널 오류로 전달하고 실제 데이터 복사 중 취소 회귀 테스트를 추가했다.

## 5. 성능 시험

같은 코덱을 사용하는 기존 루프 어댑터와 Astra core를 비교했다. 작은 파일 2,000개에서 14.59초 → 0.29초라는 결과를 얻었다. 압축은 동일 level 9와 기본 level 6을 따로 비교했으며, 느려진 경우와 출력 크기 증가도 함께 기록했다. 반디집보다 빠르다고 주장하지 않았다.

## 6. 앱 확인 — 2026-09-06

컴퓨터 화면 도구 응답이 지연된 구간 후 실행 상태를 다시 확인했다. release 앱에서 테스트용 ZIP 652개 엔트리를 열고, HTML 형태의 파일명이 실행되지 않고 글자로 표시되는 것을 확인했다. 한글 검색, 텍스트 더블클릭 미리보기, 한 파일만 선택해 스마트 추출하는 흐름을 확인하고 파일 내용도 디스크에서 대조했다. 압축 옵션과 암호 입력창도 확인했다.

## 7. 이름과 버전 확정 — 2026-09-06

사용자가 앱 이름에서 Astra를 빼고 이번 버전을 ZipLens 2.0으로 정했다. 표시 이름은 `ZipLens 2.0`, 패키지 버전은 `2.0.0`으로 맞췄다. 창 제목, 7개 언어 제목, macOS 메뉴, 프로그램 정보, 추출 보고서와 현재 안내 문서를 갱신했다. 작업 폴더와 내부 앱 식별자는 유지한다. 기존 성능 측정 원시 기록과 원본 보존 기록은 수정하지 않았다.

2.0.0 release 앱과 ZIP을 생성하고, 실제 앱 제목·macOS 메뉴·정보 화면·번들 메타데이터를 확인했다. Google Drive 읽기 지연으로 첫 빌드가 실패해 이번 실행에서만 native 설정 로더를 사용했다. 상세 검증과 명령은 VALIDATION.md 및 build-result.json에 남겼다. 이전 1.4.0 임시 결과물은 백업으로 보존한다.

## 8. 렌즈 아이덴티티 복원 — 2026-09-06

사용자가 기존 렌즈 아이콘이 앱의 아이덴티티였다고 설명하고 원본 그림을 첨부했다. 첨부 JPEG와 프로젝트의 `app-icon.jpg` 해시가 같은 것을 확인했다. 배포된 ICNS에도 이미 같은 그림이 있었다. 첫 화면의 일반 + SVG를 원래 렌즈 그림으로 교체하고, 파일을 연 후 작은 아이콘과 웹뷰 favicon에도 연결했다. 기존 제작자 이미지와 원본 프로젝트는 보존했다. 앱 이름/버전은 ZipLens 2.0 / 2.0.0을 유지한다.

첫 화면과 ZIP 목록 화면에서 렌즈 이미지 배치를 직접 확인했다. 아이콘 클릭으로 파일 선택창을 연 뒤 652개 검증용 목록도 표시했다. 새 release 앱과 ZIP을 반영하고 ICNS/PNG 원본 일치, ZIP 무결성, 새 파일 해시를 기록했다.

## 9. 렌즈를 동작 자체로 표현 — 2026-09-08

사용자가 앞선 정지 아이콘 복원 대신 UI 안에서 압축 해제는 오목렌즈의 확산, 압축은 볼록렌즈의 수렴으로 표현하고 싶다고 명확히 했다. 기존 애니메이션은 영어 상태 문구에 의존해 한국어에서 표시되지 않았고, 두 작업에 같은 볼록렌즈 기하를 사용했다. 명시적 작업 타입과 각각의 SVG 기하로 교체했다. 첫 화면·압축 설정·진행 화면을 같은 시각 체계로 맞추고, 실제 작업 중에만 광선이 왼쪽에서 오른쪽으로 흐르게 했다.

실제 앱 확인 중 수평 중앙 광선이 보이지 않는 문제를 발견했다. SVG gradient의 objectBoundingBox가 높이 0인 경로에서 유효하지 않아 userSpaceOnUse로 수정하고 회귀 검사를 추가했다. Mac 잠금으로 잠시 UI 확인이 중단됐고 사용자가 직접 잠금을 해제한 뒤 계속했다.

한국어 release 앱에서 512 MiB 입력을 ZIP으로 압축하고 512개 파일의 ZIP을 해제했다. 각각 볼록렌즈/오목렌즈와 움직이는 광선, 실측 진행률을 확인했으며 정상 완료했다. 프런트엔드 검사 8개와 타입/Vite/Tauri release 빌드를 통과했다. 기존 작업의 압축 엔진 코드는 변경하지 않았다.

512 MiB 압축 결과 및 해제된 512개 파일을 SHA-256으로 입력 데이터와 대조해 모두 일치했다. 최종 앱/ZIP을 갱신하고 코드 주석·개발자 노트·검증 기록·빌드 해시를 남겼다. 대용량 임시 검증 파일은 정리했다.

## 10. 알아서 풀기 아이콘 변경 — 2026-09-08

사용자가 알아서 풀기의 기존 SVG가 달러 기호처럼 보인다고 지적했다. 폴더와 네 방향 반짝임을 조합한 선형 SVG로 바꿨다. 기존 보라색 강조 배경과 버튼 문구는 유지하며, 장식 SVG는 aria-hidden으로 처리했다. 기능 코드 변경 없이 새 앱을 빌드했다.

별도 코드 검토에서 SVG의 여백·분리·접근성을 확인했고, 실제 14px 표시 크기에서도 활성/비활성 모양을 확인했다. 새 앱과 배포 ZIP, 검증 기록 및 해시를 갱신했다.

## 11. 압축·압축 해제 완료창 통일 — 2026-09-08

사용자가 두 완료창의 아이콘이 다르다고 지적했다. 압축은 macOS 기본 알림창, 해제는 앱 내부 체크 표시 보고서를 쓰던 구성을 하나의 완료창으로 통일했다. 성공한 압축은 볼록렌즈에 빛이 모이고 해제는 오목렌즈에서 빛이 퍼지는 정지 SVG로 표현한다. 기존 macOS 앱 아이콘은 유지한다.

완료창을 닫기 전 다음 작업이 보고서를 덮어쓰지 않게 기다리며, 암호 입력창을 먼저 정리한 다음 결과를 보여 준다. 실제 화면 검사에서 보고서가 보이지 않는 현상을 발견해 완료 표면의 블러/진입 애니메이션을 제거하고 고정 배경으로 바꿨다. 완료 후 타이머와 진행 화면도 즉시 멈춘다. 표시 문제의 단일 원인을 확정했다고 주장하지 않는다.

마우스로 상세 보기를 누른 뒤 초점이 body에 남아 Escape가 듣지 않는 WebKit 동작도 발견했다. 보고서를 연 동안 document에서 키보드 입력을 받아 닫기와 Tab 이동이 유지되게 수정했고 최종 배포 앱에서 재확인했다.

한국어 앱에서 새 ZIP 압축, AES 암호 ZIP 해제, 일반 ZIP 해제와 완료 디자인·상세 목록·버튼 표시를 확인했다. 작은 한글 파일의 압축/해제 내용은 원본 40바이트와 일치했다. 타입/Vite/Tauri 빌드와 기존 프런트엔드 테스트 8개가 통과했다. 오류·취소의 경고 분기와 큐 보호는 코드 검토 범위이며 이번 UI 시나리오에서 강제 오류·취소나 Finder 큐를 재현하지 않았다. 앱/ZIP과 개발자 노트·검증 기록·해시를 갱신했다.

## 12. 소개글 언어 병기와 GitHub 게시 준비 — 2026-09-08

사용자가 작업 결과의 기록·GitHub 업데이트와 함께, 소개글에 한국어 원문과 선택한 언어 번역을 같이 표시해 달라고 요청했다. `src/about.ts`에 한국어 원문과 영어·일본어·중국어·프랑스어·스페인어·아랍어를 구성했다. 한국어 모드에서는 원문만, 다른 언어에서는 각 한국어 문단 바로 아래에 번역을 표시한다. 제목·확인·후원 문구도 병기한다.

개인 메시지 `ERW FWS WRG`는 번역 데이터에서 분리했다. 기존 문구를 소개글 마지막에 한 번만 유지하고 아랍어 화면에서도 글자 순서가 바뀌지 않게 LTR로 격리했다. 원문은 수정하지 않았으며 번역은 HTML이 아닌 텍스트로 넣는다.

실제 앱의 한국어·영어 소개 화면을 확인했다. 영어 병기로 본문이 길어져도 창 높이를 제한하고 본문을 스크롤하도록 했다. 소개창을 다시 열 때 보이지 않는 현상이 관찰되어 진입 애니메이션·블러에 의존하지 않는 표면으로 수정했다. 아랍어 방향·문단 시작 정렬과 7개 언어의 누락 여부는 별도 코드 검토를 거쳤다. 타입/Vite/Tauri release 빌드를 통과했다.

GitHub 게시 범위는 `ZipLens_Astra`의 코드·문서·필수 리소스로 한정한다. 새 `codex/ziplens-2.0` 브랜치를 만들었으며 원본 파일과 기존 staged/unstaged 변경을 해시로 기록해 보존을 확인한다. 원본에서 복사된 개인 경로가 있는 일회성 검사 파일은 로컬에 남기고 Git에서 제외했다. 기존 기록의 검증 완료 상태와 새 clone에서 사용할 빌드 안내를 정리했다. 앱·ZIP은 로컬 산출물로 유지하며 소스 PR과 구분한다.

### GitHub 게시 결과

[PR #1: ZipLens 2.0](https://github.com/SeederPowerDrop/ZipLens/pull/1)을 만들고 `codex/ziplens-2.0` 브랜치를 게시했다. 대상은 `SeederPowerDrop/ZipLens`, 기준 브랜치는 `main`이다. 소스 게시 커밋은 `e5c72fb6908b8ba62068c40778037f8894e6f56f`이며 이 링크/검증 기록은 후속 문서 커밋으로 남긴다. 기본 브랜치 병합과 바이너리 Release는 수행하지 않았다.

Google Drive 안 Git 객체의 mmap 읽기가 timeout을 일으켜 임시 체크아웃에서 게시했다. 검토한 113개 파일을 Git blob 해시와 대조해 복사했고, 그 복사본에서 7-Zip 복구와 프런트엔드 8개 테스트를 통과했다. 테스트용 TypeScript는 기존 설치를 연결해 사용했다. 원본 작업 폴더는 기존 `feature/bandizip-overhaul` 브랜치와 최초 staged/unstaged 상태로 돌려놓았으며, 작업 파일은 삭제하거나 되돌리지 않았다.

## 13. 알아서 풀기 번역 누락 수정 — 2026-09-08

사용자가 다른 언어를 선택해도 알아서 풀기가 한국어로 남는다고 알려 주었다. 이 버튼은 HTML에 문구만 있고 번역 키와 언어 변경 시 DOM 갱신이 빠져 있었다. 7개 언어의 `btnSmartExtract`를 추가하고 기존 아이콘 보존 헬퍼에 연결했다. 소개글 및 개인 메시지에는 손대지 않았다.

타입/Vite/Tauri 빌드를 통과했으며 최신 앱에서 영어 Smart Extract, 스페인어 Extracción automática, 한국어 복원을 확인했다. 800×600 창에서 긴 스페인어 버튼 문구도 한 줄로 표시된다. 코드 검토에서 다른 문구 덮어쓰기가 없고 SVG·클릭 처리·disabled 상태가 유지됨을 확인했다. 로컬 앱/ZIP과 검증 해시를 갱신하고 같은 PR #1에 후속 수정으로 기록한다.

## 14. 40바이트 파일이 158바이트 ZIP이 된 이유 검토 — 2026-09-08

사용자가 작은 텍스트 파일의 압축 후 용량 증가를 버그인지 확인해 달라고 요청했다. 화면의 `plain-check.zip` 검증 자료와 실제 ZipLens에서 만든 동일 내용 ZIP을 모두 직접 읽었다. 두 파일은 원본 40바이트, Deflate 내용 40바이트, ZIP 부가 정보 118바이트로 총 158바이트였다. 내부 엔트리 한 개, CRC 통과, 원본 바이트/SHA-256 일치를 확인했다.

PKWARE ZIP 명세와 압축 코드도 검토했으며 이번 증가는 정상으로 판단했다. 엔진 수정이나 재빌드는 하지 않았다. 압축 내용이 증가할 때 Stored로 전환하는 방식은 별도 최적화 후보이고, 이번 사례에서는 전환해도 158바이트이므로 해결책으로 제시하지 않았다. 상세 분석은 [작은 파일의 ZIP 용량 증가 검토](ZIP_SIZE_KO.md)에 남겼다.


## 15. 기본 압축 앱 설정과 확장자 지원 확대 — 2026-09-11

사용자가 macOS 기본 압축 앱 지정과 추가 압축 확장자 지원을 요청했다. ZipLens 2.0에 종류별 기본 연결 설정창과 Launch Services 어댑터를 추가했다. Finder 선언을 8개에서 34개 확장자로 확장하고 CLI/드래그/파일 선택창의 인식 기준을 통일했다. 실제 연결 변경은 설정창에서 적용할 때 수행한다.

확장자만 늘리면 BZ2/XZ 등의 파일 목록과 크기가 누락되는 문제를 발견해 별도 스트림 해제 경로를 구현했다. 압축 TAR 내부 목록과 선택 해제, 단일 파일 스트림, CBT 별칭을 지원한다. 기본 앱 백엔드와 UI, 형식 엔진을 병렬 구현한 뒤 통합 검토에서 macOS 별칭 공유 안내, 실행 앱 이름, 저장 대화상자 대기 중 시작 요청 경합을 수정했다. 엔진 35개, 프런트엔드 9개, macOS 연결 읽기 전용 7개 검사가 통과했다. ALZ/EGG는 지원한다고 표시하지 않는다.


## 16. 후원·광고를 고려한 배포 보완과 ALZ/EGG — 2026-09-12

사용자가 합법적인 무료 배포와 많은 사람의 편리한 이용을 목표로 앞서 제안한 보완 진행을 승인했다. ESTsoft 비상업용 공식 SDK나 유료 Ark SDK를 포함하지 않고 공개된 MIT 조건의 unalz/unegg 0.2.1을 채택했다. 의존성 고지에는 원문·출처·버전·소스 해시를 포함했고, 7-Zip 26.03과 MPL 구성요소의 대응 소스를 앱 안에 직접 제공했다. 앱 자체에 새 라이선스를 지정하지 않았다.

해제 엔진, 라이선스 목록 생성, 정보 창 UI를 나누어 구현하고 교차 검토했다. 검토에서 ALZ 분할 파일 핸들 중복, EGG 상대 이름 확장과 중첩 부모 식별자 문제를 보완했다. 47개 엔진·9개 프런트엔드·7개 macOS 연결 검사가 통과했다. 라이선스 누락·변조·소스 누락·두 잠금 파일 변경을 배포 검사에서 거부하는 것도 확인했다.

실제 앱에서 EGG 한글 파일 한 개만 해제해32바이트를 대조하고, 최종 앱의 ALZ 두 파일37바이트를 대조했다. 초기 macOS 파일 선택창에서 ALZ/EGG의 열기 버튼이 비활성화되는 현상을 확인해 유형 필터를 제거하고 엔진 검증을 유지했다. 정보 창의 라이선스 버튼이 실제 앱 안의 자료 폴더를 Finder에서 여는 것도 확인했다.

포장 중 File Provider 메타데이터 복사 오류와 불완전한 로컬 서명을 확인했다. 파일 바이트·권한을 보존하고 별도 실행 파일부터 ad-hoc 서명한 뒤 앱 전체를 검사하는 포장 스크립트를 추가했다. 공식 7-Zip 입력과 서명 후 해시를 구별하고, ZIP 내용·권한·CRC 및 ZIP을 다시 푼 앱의 서명을 검증했다. Developer ID 인증서는 조회 결과0개이며 Apple 공증은 완료하지 않았다. 공개 업로드·광고/결제 기능 추가·실제 기본 앱 연결 적용은 하지 않았다.


## 17. 최종 버그·기능 점검 — 2026-09-13

사용자의 최종 검토 요청에 따라 엔진, 프런트엔드 흐름, 배포 검증을 독립 검토하고 재현된 문제를 수정했다. 원본 파일 식별자와 실제 분할 입력 목록으로 원본을 보호하고, 실패한 대상에 연결되는 링크는 게시하지 않는다. TAR 원본 크기 변경 감지, 대화상자 전체 작업 잠금과 인수 고정, 암호 제출 중 취소, macOS 창 상태 보존, helper 아키텍처·바이트 대조를 추가했다.

87개 자동 검사와 타입/Clippy/release 빌드를 통과하고 최신 앱/ZIP을 다시 만들었다. 실제 앱에서 암호화 EGG의 오류·취소·재시도, ALZ 해제, 텍스트 미리보기, 창 복원과 대기한 설정 처리, 충돌창 중 Finder 요청 순서 보장을 확인했다. ALZ/EGG 출력은 각각37바이트 원문과 일치했다. [최종 검토](FINAL_REVIEW_KO.md), [검증 기록](VALIDATION.md), build-result.json에 근거와 남은 검증 범위를 기록했다. 공개 업로드와 실제 기본 연결 변경은 하지 않았다.
