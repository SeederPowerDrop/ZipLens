# ZipLens 2.0 최종 버그·기능 점검 — 2026-09-13

점검 대상은 `ZipLens_Astra`의 현재 소스와 이 소스로 다시 만드는 macOS arm64 앱이다. 기존 63개 자동 검사는 모두 통과했지만, 별도의 오류 상황 재현에서 다음 문제를 발견해 보완했다.

| 문제 | 발생 조건과 보완 |
| --- | --- |
| 원본 압축파일 덮어쓰기 | macOS에서 대소문자 또는 Unicode 표기만 다른 이름을 동일 폴더에 풀거나 압축 결과로 저장하면 원본을 교체할 수 있었다. 실제 파일 식별자로 동일 파일을 확인한다. 하드링크도 보호하고, 둘 다 유지하는 저장은 허용한다. |
| 분할 원본의 다른 조각 덮어쓰기 | ALZ/EGG와 7Z/ZIP 분할 파일에서 첫 파일 외의 조각은 보호되지 않았다. ALZ/EGG가 실제 사용한 입력 경로와 일반적인 숫자·ZIP/RAR 분할 이름군을 보호 대상으로 포함한다. |
| 실패한 대상에 연결되는 바로가기 게시 | 일반 파일 게시가 실패했는데 연결 파일은 성공하여 기존 외부 파일을 가리킬 수 있었다. 연결 대상의 실제 게시 성공과 최종 경로를 확인한 뒤 연결 파일을 게시한다. |
| 대화상자 대기 중 작업 대상 변경 | 파일/저장/충돌 선택 중 다른 Finder 요청이 처리되면 기존 승인을 새 아카이브에 적용할 수 있었다. 사용자 동작 전체에 잠금을 유지하고, 파일·암호·선택 목록과 압축 옵션을 대기 전에 고정한다. |
| 변경 중인 파일로 손상된 TAR 생성 | TAR 계열 압축 중 원본 크기가 바뀌어도 성공으로 보고할 수 있었다. 읽은 크기를 헤더 크기와 대조하여 기존 출력 파일을 보존하고 임시 결과를 폐기한다. |
| 암호 입력 후 취소 불가 | 암호 확인 과정이 실제 해제까지 수행하는 동안 취소 버튼과 Escape가 막혔다. 취소를 엔진에 전달하고 엔진이 끝날 때까지 다음 작업을 막는다. |
| 창을 닫으면 진행 상태 소실 | macOS 닫기 버튼과 Cmd+W가 웹 화면을 파괴했다. 창을 숨겨 작업과 대화상자를 유지하고 Dock/Finder 재열기에서 복원한다. Cmd+Q는 앱 종료로 유지한다. |
| 잘못된 해제 도구가 배포 검사 통과 | 앱에 다른 실행 파일이 섞여도 서명·ZIP 검사만으로 통과할 수 있었다. 준비된 도구와 CPU 종류·실행 권한·실행 파일 바이트를 비교하며 서명 차이만 정규화한다. |

## 자동 검사 결과

총 87개를 통과했다: 엔진 61개, 화면 모델·대화상자 13개, macOS 기본 연결 7개, 배포 도구 6개. 엔진의 61개는 단위 2개, 형식 10개, ALZ/EGG 12개, 링크 게시 3개, 일반 회귀 27개, 원본 보호 7개다.

엔진 전체와 macOS 어댑터의 Clippy 검사, TypeScript/Vite 및 Tauri release 빌드를 통과했다. 고지 생성 검사는 378개 구성요소가 잠금 파일과 일치함을 확인했다. 새 의존성을 추가하지 않았다.

재현 명령은 프로젝트 폴더에서 다음과 같다.

```sh
cargo test --manifest-path astra-core/Cargo.toml --locked --offline
cargo clippy --manifest-path astra-core/Cargo.toml --locked --offline --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked --offline --lib
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --offline --lib -- -D warnings
npm test
python3 scripts/test-package-macos.py
python3 scripts/generate-third-party-notices.py --check
```

## 최종 앱·ZIP 확인

새로 빌드한 앱에서 암호화 EGG의 잘못된 암호 안내, Escape 취소, 한글 암호 재시도를 확인했다. 취소 후 출력 파일은 없었다. ALZ와 암호화 EGG 각각 2개 파일, 37바이트가 원문과 일치했다. ALZ 내부 텍스트 미리보기와 Escape 복귀도 통과했다.

결과창을 Cmd+W로 숨기고 설정 메뉴로 다시 표시하니 동일한 결과가 유지됐다. 결과창을 닫은 뒤에만 대기 중인 설정이 열렸고 33개 형식을 조회했다. 별도로 ALZ 충돌창을 띄운 동안 Finder에서 다른 ZIP을 열었을 때 기존 대상이 유지되고, 충돌창을 취소한 뒤에만 새 ZIP이 열리는 것을 확인했다. 기존 파일과 입력 압축파일도 바이트 대조로 보존을 확인했다. 유휴 상태의 Cmd+Q 종료도 확인했다.

최종 ZIP은 12,843,073바이트이며 앱 270개 파일 중 라이선스 자료는 264개다. ZIP CRC·내용·실행 권한과 앱의 로컬 ad-hoc 서명 검사를 통과했고, ZIP을 임시 폴더에 다시 푼 앱의 서명도 확인했다. 해시는 [build-result.json](build-result.json)에 기록했다.

## 검사 범위의 한계

- 확장자 36개 인식과 압축 생성 5종 지원은 유지한다. 모든 포맷의 모든 제작 프로그램·버전·암호화 변종을 검증한 의미는 아니다.
- EGG AES/LEA 및 산술 코딩 AZO는 자체 검증 자료에 포함되지 않았다. ALZ/EGG 생성은 지원하지 않는다. 세부 한도는 [ALZ/EGG 검증 자료](../astra-core/tests/fixtures/legacy/README.md)를 따른다.
- 기본 앱 설정은 조회와 입력 검증을 점검한다. 사용자의 실제 파일 연결은 바꾸지 않는다.
- 대용량 암호 해제 중 취소는 대화상자 제어 흐름 및 엔진 자동 검사로 확인했다. 해당 타이밍을 실제 화면에서 직접 실행한 것은 아니다.
- arm64 로컬 실행을 검증한다. Intel 실행, Apple Developer ID 서명·공증 및 공개 다운로드 후 Gatekeeper 통과는 별도로 남아 있다.
- Google Drive가 루트 `.gitignore`와 원본 검증 대상 파일을 읽는 과정에서 시간 초과를 반환하여 이번에는 Git 상태와 전체 원본 해시 대조를 완료하지 못했다. 수정한 프로젝트 경로는 `ZipLens_Astra` 내부로 한정했다.
