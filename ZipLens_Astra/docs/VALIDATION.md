# ZipLens 검증 요약

이 문서는 공개 앱과 개발 소스의 확인 범위 및 재현 명령을 정리합니다. 과거 검사 결과와 새 배포본의 검사를 구분하며, 통과한 검사 수를 전체 형식의 호환성 보증으로 해석하지 않습니다.

## 2.1.3 DMG·도움말 검사 — 2026-10-19

이번 변경으로 다시 실행한 자동 검사 **127개**(프런트엔드 75, 패키징 32, 빌드된 앱 CLI 20)가 통과했습니다. 별도 다국어 CLI 시나리오 **13개**, WebKit 화면 상태 **160개**도 실패 없이 통과했습니다. 서로 다른 검사 범위를 구분하며, 과거 코어 검사나 아래 2.1.2 대용량 실측을 이번 실행 수에 더하지 않습니다. WebKit 검사는 Tauri IPC·네이티브 대화상자를 모의 처리한 화면 검사이며 실제 macOS 앱의 모든 조작을 검증한 것은 아닙니다.

실제 `ZipLens_2.1.3_arm64-preview.dmg`는 **19,875,599바이트**입니다. `hdiutil` 이미지 무결성 검사와 마운트, 이미지에서 앱 전체 복사, 앱 282개 파일 대조, deep/strict 서명 및 CLI 실행 확인을 통과했습니다. 이 Mac의 `/Applications` 설치본을 2.1.3으로 업데이트하고 실제 한국어 홈을 확인하고 홈의 **사용 가이드**에서 한국어 GitHub 설명서 URL을 여는 동작을 확인했습니다. 이 대표 흐름을 모든 언어·화면의 네이티브 검증으로 확대하지 않습니다.

**Developer ID 서명·Apple 공증이 없는 ad-hoc 프리뷰입니다.** 작업 Mac의 유효한 배포 서명 인증서는 0개입니다. 별도 앱 복사본에 시험용 quarantine 속성을 적용한 Gatekeeper 검사는 **종료 코드 3 / rejected**였습니다. 따라서 DMG 무결성과 로컬 설치·실행 성공을 다른 Mac의 기본 보안 정책 통과로 해석하지 않습니다. 이 검사는 실제 GitHub 다운로드가 생성한 quarantine의 검증과도 구분합니다. 체크섬과 다운로드·설치의 단계별 상태는 [2.1.3 설치 검증](INSTALLATION_VALIDATION_2.1.3_KO_EN.md)에 기록합니다.

아래 4.36 GB ZIP, 작은 파일 10,000개, 7Z 메모리 수치는 **2.1.2의 과거 엔진 측정**이며 이번 2.1.3에서 다시 측정하지 않았습니다. 확인 범위 밖의 Mac·macOS·압축 변종에 대한 무오류 보증이나 모든 작업의 성능 개선을 주장하지 않습니다. [2.1.3 변경 안내](RELEASE_2.1.3_MULTILINGUAL.md).

압축 옵션은 필수 컨트롤 표시가 fade 애니메이션 완료에 의존하지 않도록 보완했습니다. 최신 CSS로 WebKit 160개 상태와 애니메이션을 켠 프랑스어·독일어 패널 반복 열기 6회를 통과했습니다. 이 검사는 실제 WKWebView의 모든 합성 동작을 재현한다는 뜻은 아닙니다. 실제 앱에서 한국어 홈·정보창, 영어 정보창, 프랑스어 압축 설정 표시·취소와 도움말 URL을 확인했습니다. 파일 선택 자동 조작의 제약 때문에 이번 2.1.3에서 GUI 압축·해제 왕복을 완료했다고 주장하지 않습니다.

## 2.1.2 배포본 검사 — 2026-10-18

최종 패키지와 기존 2.1.1을 사용한 대용량·다수 파일 검사 **28왕복**과 편차를 확인하기 위한 파일 10,000개 후속 **12왕복**이 모두 통과했습니다. 각 왕복에서 압축·목록·해제 성공, 전체 이름·크기·SHA-256, 원본 보존을 확인했습니다. 두 버전 합계 **40왕복 / 120개 CLI 프로세스**(2.1.1: 14왕복, 2.1.2: 26왕복)이며 아래 자동 단위 검사 수와 합산하지 않습니다.

4 GiB + 64 MiB 비희소 의사난수 단일 파일에서 새 버전 ZIP 압축/해제 중앙값은 **64.898초 / 8.505초**, 기존 버전은 **67.007초 / 8.565초**였습니다(각 2회). Python ZIP 디코더로 큰 항목 전체의 CRC·SHA-256과 ZIP64 추가필드도 별도로 검사했습니다. 512 MiB 혼합 자료는 ZIP·7Z·TAR·TAR.GZ·TAR.ZST를 각 3회 왕복했습니다.

파일 10,000개에서는 초기 새 버전 해제 중앙값이 1.120초로 기존 0.862초보다 높았습니다. 추가 6회씩 비교한 중앙값도 **0.815초 대 0.722초**로 약 0.093초 높았고 실행 범위는 겹쳤습니다. 원인을 확정하거나 모든 작업이 빨라졌다고 주장하지 않습니다. 7Z의 압축 시 표본 프로세스 트리 RSS 최고치는 **1,748.4 MiB**로 ZIP보다 컸습니다. 단일 Mac의 합성 자료·캐시 유지 조건이며 GUI 전체 성능은 측정하지 않았습니다. 구체적인 범위와 표본 메모리의 한계는 [대용량 파일 검증](LARGE_FILE_VALIDATION_2026-10-18.md)에 있습니다.

새 2.1.2 최적화 앱에서 자동 회귀 **202개**(프런트엔드 69, 코어 70, Tauri/CLI 단위 22, 패키징 21, 빌드된 앱 CLI 20)와 별도 다국어 CLI 시나리오 **13개**를 다시 실행해 통과했습니다. TypeScript/Vite와 macOS arm64 release 빌드도 통과했습니다. 이전 WebKit 화면 160개를 이번에 재실행하거나 새 검사 수에 합산하지 않았습니다.

배포 ZIP의 CRC, 실제 재추출 앱의 파일 바이트·실행 권한·deep/strict 서명, 준비한 보조 프로그램과의 일치를 확인했습니다. 설치 후 앱 282개 파일과 권한을 패키지와 대조하고, 실제 한국어 홈·정보창의 2.1.2 표시·후원란·내장 가이드·압축 설정과 닫기/취소 동작도 확인했습니다. 이 설치 후 확인을 전체 GUI 왕복 검사로 취급하지 않습니다. 버전은 **2.1.2**, macOS 내부 빌드 번호는 **2.1.3**입니다. 기존과 같은 ad-hoc 프리뷰이며 Developer ID 서명·Apple 공증 완료를 뜻하지 않습니다.

대용량 실측 조건과 결과는 [대용량 파일 검증](LARGE_FILE_VALIDATION_2026-10-18.md), 변경 사항과 다운로드는 [2.1.2 업데이트 안내](RELEASE_2.1.2_KO_EN.md)에 정리합니다.

아래의 ‘Unreleased’ 제목과 ‘설치본 2.1.1’ 표현은 **해당 검사 당시**의 상태를 보존한 기록입니다. 이번 배포의 최신 검사와 혼동하지 않도록 소스·날짜별로 구분합니다.

## 다국어 화면·파일명 점검 — 2026-10-18 (Unreleased)

한국어·영어·일본어·중국어 간체·베트남어·스페인어·프랑스어·독일어·러시아어·아랍어를 대상으로 점검했습니다. 이 항목은 아래의 앞선 소스 점검 이후 추가한 검증입니다. 공개 다운로드와 설치된 앱은 여전히 2.1.1이며, 이번 소스 변경으로 교체하지 않았습니다.

### 화면과 앱 정보

Playwright **WebKit 26.5**에서 실제 앱 HTML·CSS·이벤트 처리를 실행하고 **800×600, 480×600** 두 창 크기에서 10개 언어의 주요 8개 화면을 확인했습니다. 홈·압축 설정·정보·오프라인 가이드·암호 입력·파일 목록·파일 충돌·완료 보고서의 **160개 화면 상태**에서 검사한 가로 넘침·툴바 겹침·대화상자 주요 버튼의 화면 이탈이 없었습니다. 선택한 외국어 파일명의 표시 원문과 해제 요청 이름도 대조했습니다.

긴 번역 버튼이 동일한 너비로 눌리던 문제를 수정해 필요한 만큼 줄바꿈하도록 했습니다. 압축 암호 표시 아이콘의 위치 기준과 RTL 간격도 수정했습니다. 아랍어 모드의 혼합 언어 파일명·전체 경로는 표시 방향만 격리하며 파일명이나 내보내기에 방향 제어 문자를 삽입하지 않습니다.

정보창의 10개 언어 소개·버전·가이드·후원 주소·라이선스 버튼과 읽기 방향을 확인했습니다. 라이선스 버튼은 올바른 명령을 호출하는지 검사했으며, 이 브라우저 검사에서 Finder를 실제로 열지는 않습니다. 후원 링크·주소와 `ERW FWS WRG`는 유지했습니다.

**Tauri IPC와 네이티브 대화상자는 모의 처리**했습니다. 브라우저는 실제 WebKit이지만 macOS 앱의 WKWebView와 동일한 버전이라는 뜻은 아닙니다. 이 160개 화면 검사는 직접 GUI 조작과 구분하며, 모든 창 크기, 파일 연결 설정·내부 뷰어·진행·오류창의 전체 시각 검사를 포함하지 않습니다. 배포용 코드와 모의 처리는 분리되어 있습니다.

### 실제 macOS 앱 후속 확인 — 대표 흐름 완료

소스 `acb7ec4207d032927d4b7bcf92f25f45432592f2`를 임시 디버그 앱으로 빌드하여 macOS 15.7.5, Apple Silicon에서 확인했습니다. 설치본과 구분하도록 테스트 앱의 이름·번들 식별자만 별도로 지정했으며 앱 코드를 수정하지 않았습니다.

독일어 압축 패널의 열기·취소·재열기, ZIP 암호 안내와 스크롤 후 주요 버튼 표시를 실제 화면에서 확인했습니다. 네이티브 파일 선택창으로 10개 언어와 emoji 이름을 포함한 ZIP을 열고, 독일어에서 아랍어로 전환한 뒤에도 목록의 파일명이 유지되는지 확인했습니다. 아랍어 화면에서 새 폴더로 해제한 **파일 11개와 하위 폴더 3개(빈 폴더 1개 포함)**의 이름·파일 바이트 SHA-256·폴더 구성을 대조했습니다. 이어 같은 화면에서 해제 폴더를 `다시압축-日本語-العربية.zip`으로 압축했고, Python 표준 ZIP 디코더로 내부 파일을 독립적으로 읽어 같은 결과를 확인했습니다. 재압축 시 선택한 폴더가 최상위 항목으로 포함되는 정상 구조는 비교에서 구분했습니다. 시험 원본 파일과 ZIP의 내용도 그대로 유지되었습니다.

아랍어 정보창에서는 후원 항목을 펼치고 스크롤하여 BlueWallet 주소·QR·닫기 버튼 표시를 확인했습니다. 앞선 PR #6 소스의 첫 확인에서는 러시아어·독일어 홈, 러시아어·아랍어 정보창·내장 가이드와 실제 라이선스 폴더 열기, 독일어 비ASCII ZIP 암호 안내창을 확인했습니다. 당시의 `noWindowsAvailable` 조작 오류와 압축 패널의 빈 캡처는 이번 실행에서 재현되지 않았습니다. 원인을 확정하거나 앱 오류를 수정한 것으로 기록하지 않습니다.

이번 확인은 대표 언어의 실제 ZIP 열기·해제·재압축 흐름입니다. 10개 언어 모두의 네이티브 화면, 파일 연결 설정, 7Z 다국어 암호의 네이티브 조작이나 GUI 성능을 검증한 것은 아닙니다. 아래 자동 회귀 202개·WebKit 화면 160개·CLI 다국어 시나리오 13개는 앞선 실행 결과이며 이번에 다시 실행하거나 수동 확인 횟수를 합산하지 않았습니다. 설치된 2.1.1 앱과 공개 릴리스는 유지했습니다. 원시 화면·작업 기록은 비공개 개발 자료에 보관합니다.

### 파일명·본문·암호는 서로 다른 범위

이번 소스로 빌드한 임시 macOS 디버그 앱의 CLI에서 **13개 시나리오가 통과**했습니다. 10개 언어와 emoji, NFC/NFD 이름을 섞은 파일 13개를 ZIP·7Z·TAR·TAR.GZ·TAR.ZST, 암호 ZIP 및 암호 7Z로 왕복했습니다. 압축 파일 자체의 외국어 이름, 목록·전체/명시적 선택 해제, 이름의 정확한 일치·SHA-256·원본 보존을 확인했습니다. 코어 회귀에는 메모리 읽기와 일부 파일만 선택하는 해제도 포함합니다.

구형 ZIP에는 다음과 같은 차이가 있었습니다.

| 파일명 저장 방식 | 이번 검사 |
|---|---|
| UTF-8 및 유효한 Unicode Path 확장필드 | 복원 성공 |
| CP949 무태그, UTF-8 바이트 무태그 | 복원 성공 |
| CP932·GBK·CP437 + 유효한 Unicode Path 확장필드 | 복원 성공 |
| CP932·GBK·CP437 무태그 | 이름 오해석을 재현. 현재 자동 판별 지원 범위 밖 |

무태그 구형 ZIP은 한국어 CP949 호환 해석을 사용하므로 모든 지역 인코딩을 판별할 수 없습니다. 화면 언어를 바꾸어도 이름을 복구하지 않습니다. 필요하면 제작자에게 UTF-8 ZIP이나 7Z로 다시 만들어 달라고 요청하세요. 내부 텍스트 미리보기는 UTF-8이며, 다른 인코딩의 본문은 해제 후 해당 인코딩을 지원하는 편집기로 확인해야 합니다. 압축·해제는 본문의 언어나 인코딩을 변환하지 않습니다.

번들 7-Zip의 ZIP 생성은 비ASCII 암호에서 실패하는 것을 AES/ZipCrypto와 UTF-8 로케일 세 가지에서 재현했습니다. 이제 GUI와 코어에서 출력 생성 전에 검사하고, 10개 언어로 안내합니다. ZIP 생성에는 영문·숫자·기호를 사용하고 다국어 암호에는 **7Z**를 선택하세요. 검사한 엔진의 허용 경계는 U+0020–U+007F입니다. 이 제한을 파일명이나 기존 아카이브 해제 암호에 적용하지 않았습니다.

### 성능과 자동 검사

설치된 release 2.1.1 CLI, Apple Silicon, macOS 15.7.5에서 ZIP **1,000개 파일 × 1KiB**를 ASCII/Unicode 이름으로 각각 세 번 교차 실행한 중앙값입니다. 프로세스 시작 시간을 포함하고 GUI는 제외합니다.

| 파일명 | 압축 | 목록 | 해제 |
|---|---:|---:|---:|
| ASCII | 40.7ms | 11.7ms | 69.5ms |
| Unicode | 46.0ms | 9.6ms | 70.8ms |

이 작은 표본에서 비정상적인 지연은 관측하지 않았습니다. 이름 길이·파일 수·저장 장치·형식에 따라 달라지며, 모든 언어와 자료에서 같은 속도를 보장하지 않습니다. 새 디버그 앱의 실행 시간을 release 성능과 직접 비교하지 않았습니다.

- ZIP64 항목 **65,537개**의 목록과 마지막 항목 선택 해제, Unicode 조합 방식이 다른 이름의 압축 충돌 거부, FIFO·디렉터리 입력 거부와 일반 파일을 가리키는 심볼릭 링크 허용. ZIP64 검사는 작은 항목으로 개수 경계를 확인했으며 대용량 파일 처리량 검사는 아닙니다.

### 보고서 모델 측정

Node.js 24.11.1, macOS Apple Silicon에서 보고서 크기 조회를 측정했습니다. 1,000건 준비 실행 후 각 조건을 3회 실행하고 중앙값을 기록했습니다. 각 측정 전 GC를 호출하고, 결과 개수와 크기 합계가 같은지도 확인했습니다.

| 항목 수 | 이전 접미사 전체 검색 | 개선한 인덱스 기반 보고서 모델 |
|---:|---:|---:|
| 10,000 | 3,365.299ms | 11.596ms |
| 100,000 | 측정하지 않음 | 134.724ms |

공개 재현 스크립트의 별도 실행에서는 10,000건 중앙값이 2,482.790ms → 6.207ms, 개선 후 100,000건은 69.451ms였습니다. 시스템 부하와 캐시에 따라 절대 시간은 달라지므로 특정 배수의 앱 전체 가속을 보장하지 않습니다.

입력은 `folder/item-000000.txt`부터 시작하는 고유 경로와 순차 크기이며, 모든 항목이 성공한 보고서를 사용했습니다. 이전 코드는 결과마다 `entries.find(entry => path.endsWith(entry.path))`를 실행하여 10,000건에서 50,005,000회 비교합니다. 개선 코드는 [`buildReportRows`](../src/report-model.ts)로 한 번 인덱싱합니다. 이 값은 **순수 메타데이터 모델의 시간**이며 DOM 렌더링, 파일 저장, 압축·해제 처리량이나 앱 전체 속도를 뜻하지 않습니다. 100,000건의 이전 코드 시간을 추정값으로 보고하지 않습니다.

변경한 부분만 다시 확인하려면 `ZipLens_Astra/`에서 실행합니다. 전체 빌드·패키징·CLI 명령은 아래 [재현 명령](#재현-명령)에 있습니다.

```sh
node --experimental-strip-types --test tests/report-model.test.ts tests/report-dialog.test.ts
cargo test --manifest-path astra-core/Cargo.toml --locked --test regressions
cargo test --manifest-path astra-core/Cargo.toml --locked --test zip64
node --experimental-strip-types --expose-gc scripts/benchmark-reports.mjs
```

[`benchmark-reports.mjs`](../scripts/benchmark-reports.mjs)는 위 측정 방법을 재현해 stdout에 JSON 결과를 출력합니다. 실행 환경과 부하에 따라 시간은 달라집니다. 원시 측정 기록은 비공개 개발 자료로 보관합니다.

### 실제 GUI 확인과 남은 범위

이번 소스로 만든 **임시 디버그 앱**에서 네이티브 파일 선택창 → 스마트 해제 → 결과 상세 → CSV 저장을 직접 조작했습니다. 직접 만든 `a.txt` 1바이트와 `nested/a.txt` 900바이트가 올바른 크기와 절대 출력 경로로 내보내지는지, CSV 수식 방지 처리와 실제 해제 바이트가 맞는지 확인했습니다. 이는 해당 흐름의 GUI 확인이며 새 릴리스·설치 프로그램·전체 GUI 검증은 아닙니다.

설치되어 있던 2.1.1 앱에서는 파일 선택창·목록·Unicode 이름의 파일 3개와 빈 폴더 해제·중복 이름 보존을 별도로 확인했습니다. 이 관찰은 위 디버그 앱 검사와 구분합니다.

이번 점검은 이 Apple Silicon Mac에서 수행했습니다. Intel Mac과 다른 장비·macOS 버전의 실행, 외장 디스크 연결 해제, 저장 공간 부족 상황은 추가 실전 확인이 필요합니다. 특정 macOS 버전 전체와 모든 파일 시스템·압축 변종을 보증하지 않습니다.

## 실제 이미지 왕복 검사 — 2026-10-10

Apple Silicon, macOS 15.7.5의 2.1.1 앱 실행 파일에서 GUI와 같은 엔진을 사용하는 CLI로 검사했습니다. DNG 728개와 HEIC 1개, 총 **729개 / 26,583,788,836바이트(26.58GB)**를 다섯 ZIP 묶음으로 압축·해제했습니다.

- 모든 해제본의 파일명·크기·SHA-256이 원본과 일치했습니다. 작업 전후 원본의 해시와 파일 목록·크기·수정 시각·권한도 유지되었습니다.
- 5개 ZIP 중 4개에서 중앙 디렉터리 오프셋이 4GiB를 넘었습니다. 그중 5.61GB ZIP64의 첫 항목과 4GiB 이후 마지막 항목은 Python 표준 ZIP 디코더로도 독립 복원하여 해시를 대조했습니다.
- 실제 이미지 표본으로 7Z·TAR·TAR.GZ·TAR.ZST 왕복, AES-256 ZIP의 암호 없음·오류 거부와 정상 복원을 확인했습니다. 선택 해제와 같은 목적지의 중복 파일 보존도 확인했습니다.
- 실전 왕복 검사 **10묶음**, 당시 프런트엔드 **56개**, 앱 CLI **18개**가 각각 통과했습니다.
- 전체 ZIP 출력은 약 **24.94GB**로, 입력보다 약 **6.20%** 작았습니다. 압축 합계 475.88초, 해제 합계 69.79초는 이 Mac에서 관측한 값이며 원본 해싱·추가 검사 시간은 제외했습니다. 다른 시스템이나 앱과의 성능 비교값은 아닙니다.

## 확인 범위와 한계

- 위 실전 검사는 다섯 묶음으로 실행했습니다. 26.58GB 단일 압축 파일, 개별 4GiB 초과 입력 파일 또는 65,535개 초과 항목의 실전 검사를 뜻하지 않습니다.
- SHA-256 대조는 이미지와 내부 EXIF를 포함한 파일 바이트의 보존을 확인합니다. 추출 결과의 ACL·확장 속성·리소스 포크와 모든 파일시스템 메타데이터 보존을 검증한 것은 아닙니다.
- CLI 검사를 GUI 드래그앤드롭·파일 선택창·진행률·취소·분할 압축의 실제 조작 검사로 대신하지 않습니다.
- Apple Silicon용 실행 결과이며 Intel Mac 실행은 검증하지 않았습니다. ad-hoc 프리뷰는 Developer ID 서명·Apple 공증 완료를 뜻하지 않습니다. [macOS 실행 안내](MACOS_LAUNCH_KO.md)를 참고하세요.
- RAR·ALZ·EGG를 포함한 모든 형식의 모든 변종을 검증하지 않았습니다. ALZ/EGG의 크기 한도와 확인한 변형은 [테스트 자료 안내](../astra-core/tests/fixtures/legacy/README.md)에 명시합니다.
