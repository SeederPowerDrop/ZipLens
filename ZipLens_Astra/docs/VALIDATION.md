| TypeScript 타입 검사 + Vite production bundle | 통과 |
| Tauri macOS debug 앱 빌드 | 통과 |
| Tauri macOS release 앱 빌드 | 통과, 최종 결과는 아래 경로 |

| 7-Zip 공식 배포 파일/실행 파일 SHA-256 | provenance와 일치 |
| ZIP/TAR/GZIP/ZSTD/7Z 테스트 결과 | 내용 바이트 대조 통과 |
| 자체 ZIP 성능 시험 | 1회 워밍업 + 3회 교차 반복, 모든 결과 내용 검증 |

최종 앱: `../release_build/ZipLens 2.0.app`. release 빌드는 Apple Silicon용입니다. 동봉된 7-Zip은 arm64/x86_64 universal입니다. 앱 코드의 Intel 빌드/실행은 시험하지 않았습니다.

전체 158개 파일 대조는 앞서 모두 일치했습니다. 마지막 전체 재검사는 Google Drive의 원본 7-Zip 매뉴얼 파일 읽기에서 지연되어 제한 시간 내 끝나지 않았습니다. 원본 소스 코드는 별도로 다시 검사해 변경 없음을 확인했으며 `original-verification.json`에 구분해 기록했습니다.

## 실제 UI 확인

컴퓨터 화면 도구로 최적화 빌드를 실행해 다음 흐름을 확인했습니다.

1. 앱 이름·한국어 초기 화면·중복 없는 툴바 라벨.
2. 생성한 테스트용 ZIP(652개 엔트리) 파일 선택 및 목록 표시.
3. `<img src=x onerror=alert(1)>.txt`가 HTML 실행 없이 글자로 표시됨.
4. `한글` 검색으로 결과 1개 표시.
5. `한글 안내.txt` 더블클릭으로 실제 텍스트 내용 표시.
6. 전체 선택 해제 후 한 파일만 선택해 알아서 풀기. 성공 보고서와 디스크 파일 내용을 대조함.
7. 압축 레벨·파일/폴더 선택·분할·암호 체크 시 입력창과 AES 선택 표시.

이것은 모든 버튼·모든 언어·모든 Finder 이벤트를 자동으로 검사하는 GUI 테스트 모음은 아닙니다. 초기 화면 도구 지연과 파일 선택창 조작 오류 후 재시도하여 위 흐름을 확인했습니다.

## 미검증

실제 반디집과의 직접 대결, 4 GiB 이상 ZIP64 실물, 손상/분할 RAR 변종, 모든 ZIPX 알고리즘, 외장 디스크·네트워크 볼륨, 디스크 부족·전원 종료, Intel 앱 실행, 앱 번들 xattr/리소스 포크/서명 보존, 코드 서명·Apple 공증, fuzzing/전체 의존성 보안 감사는 수행하지 않았습니다.

## ZipLens 2.0 이름 확정 후 확인 — 2026-09-06

- TypeScript 타입 검사, Vite production, Tauri release 앱 재빌드 통과.
- 배포 앱의 `CFBundleName`/`CFBundleDisplayName`은 `ZipLens 2.0`, `CFBundleShortVersionString`/`CFBundleVersion`은 `2.0.0`임을 확인. NPM/Rust 패키지와 자체 lockfile 버전도 일치.
- 실제 새 앱을 실행해 창 제목, macOS 앱 메뉴, 프로그램 정보의 `ZipLens 2.0 / Version 2.0.0` 표시 확인.
- `release_build/ZipLens_2.0.0_arm64.zip`의 ZIP CRC와 내부 앱 이름 확인. 파일 해시는 `build-result.json`에 기록.
- 앞선 25개 core/4개 UI 함수 테스트 결과는 기능 코드가 동일한 명칭 변경 전 검증 기록이다. 이번에는 이름·버전 변경에 맞춘 빌드/메타데이터/UI 확인을 수행했다.

첫 빌드는 Vite의 기본 설정 로더가 Google Drive 상위 폴더의 원본 `package.json`을 읽다가 timeout으로 실패했다. 원본 수정 없이 Node 24의 native 설정 로더로 빌드를 완료했다. 재현 명령은 `build-result.json`의 `build_command`를 참고한다. 일반 빌드 설정은 유지한다.

## 광학 동작 UI — 2026-09-08

- `npm test`: 기존 UI 함수 4개 + 렌즈 회귀 4개, 총 8개 통과. 렌즈 검사는 번역된 문구/미리보기/정지/미정 진행률/중앙 광선/gradient ID를 포함한다. 테스트의 DOM stub은 실제 렌더링을 대신하지 않는다.
- TypeScript 타입 검사, Vite production 및 Tauri release 빌드 통과.
- 실제 한국어 macOS release 앱 첫 화면: 오목렌즈 확산. 압축 설정: 볼록렌즈 수렴.
- 실제 512 MiB ZIP 압축: 볼록렌즈로 모이는 5개 광선과 이동하는 흰색 하이라이트, 작업명/파일명/진행률(관찰 프레임 2~3%) 확인. 완료 대화상자 확인.
- 실제 ZIP 512개 파일/512 MiB 해제: 오목렌즈 확산과 이동하는 광선, 진행률(관찰 프레임 11~16%) 확인. 512개 성공 보고서 확인. 이 수치는 동작 확인 프레임이며 성능 벤치마크가 아니다.
- 코드/회귀 검증에서 종료·취소 요청·암호 대기 시 광선 정지를 확인했다. 이번 실제 UI 작업에서 취소/암호 대기 시나리오를 추가로 실행하지는 않았다.
- 동작 줄이기는 CSS 미디어 쿼리와 우선순위를 검토했다. 사용자의 macOS 설정을 변경한 실기기 시험은 수행하지 않았다.

ZIP 압축 결과를 다시 읽어 입력 512 MiB와 SHA-256 일치를 확인했다. 해제된 512개 파일도 각 원본 블록과 모두 일치했다. 최종 배포 앱과 빌드 바이너리 해시가 같고, 배포 ZIP의 CRC 검사도 통과했다. 큰 임시 검증 자료는 결과 대조 후 정리했다.

## 공통 광학 완료창 — 2026-09-08

- 한국어 macOS 앱에서 한글 텍스트 파일 ZIP 압축 완료: 볼록렌즈 수렴, 압축 파일 1개 생성 문구, Finder/닫기만 표시. Tab으로 닫기에서 Finder 버튼으로 순환하고 Escape로 닫힘을 확인했다.

- 최종 `release_build` 앱에서 일반 ZIP 해제 → 상세 보기 마우스 클릭 → Escape 닫기 후 기본 버튼 활성화와 목록 복원을 확인했다. 완료 전의 진행 화면·계속 증가하는 타이머는 결과창 뒤에 남지 않는다.
- 생성한 ZIP 내부 파일과 암호 ZIP 및 일반 ZIP의 해제 파일을 입력 40바이트와 대조했다. SHA-256: `2cffafff5be7df83757c255789e7108b3e606cfba7db0be2d576f10c2b2bfeca`. 성능 측정이 아닌 결과 무결성 확인이다.
- 취소/오류 시 경고 아이콘, 작업별 버튼 초기화, Finder 실패 시 상위 폴더 처리, 닫기 전 큐 대기는 별도 코드 검토를 거쳤다. 이번 UI 검사에서 강제 오류·취소·Finder 대기열 시나리오를 실행한 것으로 간주하지 않는다.
- 최종 앱/빌드 바이너리 SHA-256 일치, 앱 이름/버전 2.0.0, 배포 ZIP CRC를 확인했다. 현재 해시는 `build-result.json`에 기록한다.

## 한국어 원문과 소개글 번역 — 2026-09-08

- 타입 검사, Vite production, Tauri release 빌드 통과. 압축 엔진/작업 흐름은 변경하지 않았다. 앞선 25개 Rust/8개 프런트엔드 테스트 기록은 그대로 보존하며 이번 소개글 수정의 자동 UI 테스트로 간주하지 않는다.
- 실제 800×600 macOS 앱의 한국어 소개 화면에서 원문·버전·마지막 개인 메시지를 확인했다. 영어 선택 후 한국어와 영어 문단, 병기된 제목/확인 버튼, 높이가 제한된 본문 배치를 시각 확인했다.
- 7개 언어의 모든 문단, 한국어 원문 일치, 개인 메시지의 단일 고정 위치, type-only import를 별도 코드 검토했다. 아랍어 번역은 RTL/읽기 시작 정렬, 한국어와 개인 메시지는 LTR이다. 영어·한국어 외 언어의 네이티브 렌더링을 모두 실행한 것은 아니다.
- 개인 메시지는 `translate="no"`인 전용 문단에 한 번만 있고 번역 갱신 함수는 해당 DOM을 수정하지 않는다.
- 재빌드 앱의 버전/바이너리 일치와 배포 ZIP CRC를 확인하고 `build-result.json`을 갱신했다.

GitHub 게시용 임시 체크아웃에서도 동봉 7-Zip 복구를 확인했다. 처음에는 의존성이 없는 상태여서 렌즈 검사에 필요한 TypeScript를 찾지 못했고, 기존 설치 의존성을 연결한 뒤 `npm test` 8개가 모두 통과했다. 이는 새 환경에서의 `npm ci` 설치 검증을 의미하지 않는다. 게시한 변경 경로는 모두 `ZipLens_Astra/**`이며 원본 6개 수정 파일의 내용과 staged/unstaged diff 해시가 작업 시작 시점과 일치했다.
