# ZipLens 코드 검토와 개선 방향

검토 시작: 2026-09-05. 마무리 검증: 2026-09-06. 대상: 원본 작업 폴더의 현재 파일과 미커밋 변경 전체. 원본 보존 기준은 `original-manifest.json`입니다.

## 판단

압축 파일을 열어 내용과 선택 용량을 보고 일부만 푸는 흐름, 한글 ZIP 파일명 처리, Rust/Tauri 구성은 실제로 확장할 기반이 있습니다. 다만 원본은 **데이터 보존·경로 안전성·에러 보고·대량 파일 처리에서 중요한 결함**이 있어, 반디집 수준의 완성도라고 판단할 수 없었습니다.

Astra는 아래 결함을 우선 수정했습니다. 모든 포맷과 운영체제에서 검증한 상용 제품과 같거나 더 뛰어나다는 주장은 하지 않습니다. 특히 반디집과 같은 장비·데이터·설정의 직접 비교는 이번에 수행하지 않았습니다.

## 확인한 결함과 조치

| 중요도 | 원본에서 확인한 문제 | ZipLens 2.0 조치 |
|---|---|---|
| P0 | `extract_archive` 덮어쓰기가 `root_items`에 해당하는 기존 폴더를 `remove_dir_all`로 먼저 삭제. 선택하지 않은 파일까지 유실 가능 | 기존 폴더를 병합하며 검증한 파일만 개별 교체. 손상 ZIP은 기존 데이터에 반영하지 않음 |
| P0 | ZIP의 `..` 문자열 제거는 안전한 경로 검사가 아니며, 심볼릭 링크 및 목적지 링크를 따라 외부에 쓸 수 있음 | 절대/상위 경로 거부, 경로 구성요소 검사, 링크는 마지막에 생성, 외부/순환/깨진 링크 거부, 목적지 링크 차단 |
| P0 | 7z 기본 추출 함수에 검증되지 않은 엔트리 경로를 전달 | 취약 라이브러리 제거. 최신 공식 7-Zip 사용, 목록 사전 검사 및 임시 결과 검증 |
| P1 | 파일명·에러 문자열을 `innerHTML`에 직접 삽입, CSP 없음 | HTML 이스케이프, CSP 설정, 원격 폰트 제거, 보고서 CSV 수식 삽입 방지 |
| P1 | ZIP 파일 하나마다 전체 중앙 목록 재파싱, 선형 선택 탐색 반복 | 공유 중앙 목록 + 독립 파일 읽기 위치, 최대 8개 작업 단위, HashSet 선택 검사 |
| P1 | native ZIP에 암호가 없으면 재입력 오류 대신 실패 보고서가 반환됨 | `PASSWORD_REQUIRED`를 일관되게 반환, 추출/미리보기 재시도, 중복 제출 차단 |
| P1 | 비암호 ZIP에서는 `split_size`를 무시, TAR 암호도 무시 | 분할 ZIP을 7-Zip으로 보내고, 지원하지 않는 옵션은 명시적 오류 |
| P1 | 결과 ZIP을 입력 폴더 내부에 만들면 자기 자신을 압축하거나 원본을 덮어쓸 수 있음 | 출력은 입력 폴더 외부에만 허용, 입력과 동일 파일 거부, 완성된 출력만 교체 |
| P1 | 손상·권한 오류 후에도 일부 경로를 성공 처리, 중복 이름 변경 후 예전 경로 반환 | 실제 출력 경로 반환, 생성·복사·CRC·flush 오류 전달, 오류 결과 정리 |
| P1 | 동기 디코딩을 async 커맨드 안에서 직접 수행, 취소 플래그가 실제 UI에 연결되지 않음 | blocking 작업 풀로 분리, 작업별 취소 토큰, 외부 프로세스 종료·회수 |
| P2 | 7z에 ZIP용 `-mcp=949`를 무조건 적용 | 제거. 한글 CP949 처리는 native ZIP에서 명확하게 지원 |
| P2 | 고정 PID 임시 폴더·목록 파일 재사용, 미리보기 메모리 무제한 | 무작위 전용 임시 폴더, 20 MiB 실제 읽기 제한, 앱 종료 시 외부 미리보기 정리 |
| P2 | 목록 검색을 숨김, 모든 행 재생성, 클릭 재렌더링으로 더블클릭을 방해 | 검색 복구, 300행 페이지, 선택 클릭 지연, Enter로 열기 |
| P2 | 디렉터리 표시 누락, TAR.GZ 스마트 폴더명이 `.tar`로 남음, 언어 중복 라벨 | 디렉터리 필드, 복합 확장자 처리, 언어 저장 및 라벨 갱신 수정 |
| P2 | 시작 이벤트를 800 ms 후 한 번 보내므로 웹뷰 준비가 늦으면 유실. Finder Opened 미처리 | 준비된 프런트엔드가 대기 요청을 가져가는 방식과 macOS Opened 처리 |

## 의존성 검토

원본 `sevenz-rust 0.6.1`의 추출 경로 문제는 공개 권고와 일치합니다. 해당 프로젝트는 중단됐고 수정판이 없다고 안내되어 있어 의존성을 제거했습니다. [RustSec RUSTSEC-2026-0245](https://rustsec.org/advisories/RUSTSEC-2026-0245.html)

원본 `tar 0.4.44`에는 링크를 따라 외부 디렉터리 권한을 변경하는 문제가 있습니다. ZipLens 2.0 lockfile은 0.4.46이며, 경로를 검증하는 자체 쓰기 경로를 사용합니다. [RustSec RUSTSEC-2026-0067](https://rustsec.org/advisories/RUSTSEC-2026-0067.html)

원본 lockfile의 `zip 2.4.2`는 별도 ZIP 라이브러리 권고의 수정 범위에 이미 속합니다. 이것과 **앱 자체 추출 코드의 링크 처리 결함**을 구분해야 합니다. [RustSec RUSTSEC-2025-0168](https://rustsec.org/advisories/RUSTSEC-2025-0168.html)

동봉된 7-Zip은 원본의 24.09에서 공식 26.03으로 교체했습니다. 공식 HTTPS 배포 경로와 다운로드·실행 파일 해시는 `sidecar-provenance.json`에 있습니다. 전체 의존성에 대한 전문 보안 감사나 fuzzing을 완료했다는 의미는 아닙니다. [7-Zip 공식 다운로드](https://www.7-zip.org/download.html)

## 다음 개발 우선순위

1. **배포 전 호환성**: 실제 RAR/ZIPX/분할 RAR/암호 ZIP/손상 중앙 목록·ZIP64 4 GiB 이상·APFS 대소문자 구분 볼륨·외장 디스크를 fixture로 추가. 앱 번들 메타데이터와 전원/디스크 부족 시험을 가장 먼저 수행.
2. **데이터 처리 마무리**: 폴더 권한·시간 보존 정책, 동일 작업 내 대상 파일 변경 감지, 게시 단계 전체 롤백/재개, 남은 공간 표시와 경고, 외부 프로세스의 실시간 진행률.
3. **macOS 사용성**: Finder Sync/Quick Action 패키징, Cmd+O 등 메뉴 단축키, 일관된 번역, 작업 큐, 충돌 건너뛰기, UI 자동 테스트 도구 구축.
4. **압축 성능**: incompressible 파일 Store 전환, 스트리밍 병렬 ZIP 제작, 버퍼·워커 수를 SSD/외장 디스크별로 측정. 대용량 한 파일은 알고리즘 자체 병렬화가 필요하므로 단순 스레드 증가로 해결되지 않음.
5. **고급 기능**: 비파괴 ZIP 편집, 별도 무결성 테스트, 이미지 디코드 한도, macOS Keychain 암호 관리자. 손상 복구와 암호 찾기는 기본 데이터 안전성을 완성한 다음 진행.

## 현재 제한을 알아두기

검증을 위해 먼저 풀어 두므로 목적지 볼륨에 임시 공간이 필요합니다. 일반 덮어쓰기는 **파일별** 교체이며, 최종 반영 도중 오류/취소가 발생하면 이미 성공한 파일은 남습니다. 전체 폴더를 한 번에 되돌리는 트랜잭션은 아닙니다.

대소문자·유니코드 정규화가 겹치는 엔트리는 보수적으로 거부합니다. 외부/깨진 링크, 7-Zip 경로의 링크, Keep Both에서 루트 폴더를 가로지르는 링크는 제한합니다. 이는 호환성상의 제한이므로 실제 앱 번들을 배포할 때 추가 구현이 필요합니다.

외부 추출 엔진은 별도 OS 샌드박스에 가두지 않았습니다. 1 TiB/백만 엔트리 제한은 완전한 압축 폭탄 방어가 아니며, 이미지 픽셀 수 제한도 추가해야 합니다. 같은 사용자 권한의 다른 프로세스가 목적지 폴더를 동시에 교체하는 경쟁 조건까지 완전히 차단한 것은 아닙니다. 외부 7-Zip에 전달하는 암호는 현재 프로세스 인수에 들어가며, 향후 파이프 기반 전달로 개선할 대상입니다.
